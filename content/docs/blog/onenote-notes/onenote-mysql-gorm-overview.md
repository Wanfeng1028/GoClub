<p><strong>GORM 全面详细讲解</strong></p><p><a id="heading_0"></a><strong>Go语言GORM全面详细讲解</strong></p><p>GORM（Go ORM）是Go语言生态中最流行的<strong>全功能ORM框架</strong>，专为Go语言设计，支持MySQL、PostgreSQL、SQLite、SQL Server等主流数据库，提供了优雅的链式调用、自动迁移、关联查询、事务管理等核心能力，大幅降低Go语言操作数据库的开发成本，是企业级Go项目的首选数据库操作框架。</p><p><a id="heading_1"></a><strong>一、GORM核心版本说明</strong></p><p>目前GORM有两个主要版本，<strong>推荐新项目直接使用GORM v2</strong>（功能更完善、性能更优、API更统一），v1已进入维护阶段，不再新增功能：</p><ul><li><strong>GORM v1</strong>：旧版核心包github.com/jinzhu/gorm，仅支持Go 1.12+，部分功能设计冗余；</li><li><strong>GORM v2</strong>：新版核心包gorm.io/gorm，要求Go 1.16+，重构了底层架构，新增批量操作、预加载优化、自定义插件等功能，是当前的主流版本。</li></ul><p>下文所有讲解均基于<strong>GORM v2</strong>。</p><p><a id="heading_2"></a><strong>二、快速入门：安装与基础使用</strong></p><p><a id="heading_3"></a><strong>2.1 安装核心包与数据库驱动</strong></p><p>GORM v2将<strong>核心框架</strong>与<strong>数据库驱动</strong>解耦，需分别安装核心包和对应数据库的驱动（以最常用的MySQL为例）：</p><table><tr><td><p>Bash<br /># 安装GORM v2核心包<br />go get gorm.io/gorm<br /># 安装MySQL驱动（GORM官方推荐的mysql驱动，基于go-sql-driver/mysql封装）<br />go get gorm.io/driver/mysql</p></td></tr></table><p>其他数据库驱动安装：</p><table><tr><td><p>Bash<br /># PostgreSQL<br />go get gorm.io/driver/postgres<br /># SQLite<br />go get gorm.io/driver/sqlite<br /># SQL Server<br />go get gorm.io/driver/sqlserver</p></td></tr></table><p><a id="heading_4"></a><strong>2.2 数据库连接</strong></p><p>通过gorm.Open建立数据库连接，第一个参数为驱动实例，第二个参数为GORM配置项（gorm.Config{}）。</p><p><a id="heading_5"></a><strong>MySQL连接示例（最常用）</strong></p><table><tr><td><p>Go<br />package main<br /><br />import (<br />  "gorm.io/driver/mysql"<br />  "gorm.io/gorm"<br />)<br /><br />func main() {<br />  // 1. 构造MySQL DSN（数据源名称），格式：user:password@tcp(host:port)/dbname?charset=utf8mb4&amp;parseTime=True&amp;loc=Local<br />  // 说明：parseTime=True 让GORM能解析MySQL的时间类型，loc=Local 使用本地时区<br />  dsn := "root:123456@tcp(127.0.0.1:3306)/gorm_demo?charset=utf8mb4&amp;parseTime=True&amp;loc=Local"<br />  <br />  // 2. 建立数据库连接，返回*gorm.DB（GORM核心操作对象，全局复用即可，无需每次创建）<br />  db, err := gorm.Open(mysql.Open(dsn), &amp;gorm.Config{})<br />  if err != nil {<br />    panic("数据库连接失败：" + err.Error())<br />  }<br /><br />  // 3. （可选）获取底层sql.DB，设置连接池参数（关键：避免高并发下连接耗尽）<br />  sqlDB, _ := db.DB()<br />  // 设置最大打开连接数（同时与数据库建立的最大连接数）<br />  sqlDB.SetMaxOpenConns(100)<br />  // 设置最大空闲连接数（连接池中保持的空闲连接数）<br />  sqlDB.SetMaxIdleConns(20)<br />}</p></td></tr></table><p>关键注意：*gorm.DB是<strong>并发安全</strong>的，项目中建议全局初始化一次，所有goroutine复用即可。</p><p><a id="heading_6"></a><strong>2.3 gorm.DeletedAt `gorm:"index"` // 软删除字段：带索引，开启软删除后，删除操作变为更新该字段<br />}<br /><br />func main() {<br />  dsn := "root:123456@tcp(127.0.0.1:3306)/gorm_demo?charset=utf8mb4&amp;parseTime=True&amp;loc=Local"<br />  db, _ := gorm.Open(mysql.Open(dsn), &amp;gorm.Config{})<br /><br />  // 自动迁移：根据模型创建/更新表结构（仅新增，不删除）<br />  // 传模型指针，支持同时迁移多个模型：db.AutoMigrate(&amp;User{}, &amp;Article{})<br />  err := db.AutoMigrate(&amp;User{})<br />  if err != nil {<br />    panic("表结构迁移失败：" + err.Error())<br />  }<br />}</p></td></tr></table><p><a id="heading_8"></a><strong>常用GORM Tag说明（开发必备）</strong></p><table><tr><td><p>Tag键</p></td><td><p>作用</p></td></tr><tr><td><p>primaryKey</p></td><td><p>标记该字段为主键（支持复合主键：多个字段加该tag）</p></td></tr><tr><td><p>autoIncrement</p></td><td><p>主键自增（仅支持数值类型）</p></td></tr><tr><td><p>size:n</p></td><td><p>设置字段长度（如size:50，对应MySQL <p>MySQL 和 Redis 的配置文件格式选择是一个常见的问题。以下是对 cnf 格式和 YAML 格式的详细解释：</p><p>### cnf 格式配置文件的用途</p><p>**1. 原生支持**</p><p>- **MySQL**：my.cnf 是 MySQL 的官方默认配置文件格式，MySQL 服务启动时会自动读取</p><p>- **Redis**：redis.conf 是 Redis 的官方默认配置文件格式，Redis 服务启动时会自动读取</p><p>**2. 格式特点**</p><p>- 采用 INI 风格的配置格式，使用 `[section]` 划分不同配置区域</p><p>- 配置项采用 `key = value` 的形式，简洁明了</p><p>- 支持注释（以 `#` 开头）</p><p>- 是数据库和缓存服务的标准配置格式，被广泛使用</p><p>**3. 适用场景**</p><p>- **直接运行服务**：当直接在服务器上安装和运行 MySQL/Redis 时，使用 cnf 格式的配置文件</p><p>- **容器化部署**：在 Docker 容器中运行时，通常通过挂载 cnf 配置文件来覆盖默认配置</p><p>- **服务启动参数**：可以通过 `--defaults-file` 参数指定配置文件路径</p><p>### YAML 格式配置文件的用途</p><p>**1. 编排工具支持**</p><p>- **Docker Compose**：使用 docker-compose.yml 来定义和运行多容器 Docker 应用</p><p>- **Kubernetes**：使用 YAML 文件来定义 Pod、Service、Deployment 等资源</p><p>**2. 格式特点**</p><p>- 采用缩进的层次结构，更具可读性</p><p>- 支持列表、嵌套对象等复杂数据结构</p><p>- 配置更加结构化，适合定义多组件的关系</p><p>**3. 适用场景**</p><p>- **容器编排**：在使用 Docker Compose 或 Kubernetes 时，使用 YAML 文件定义服务配置</p><p>- **应用配置管理**：作为应用程序的配置文件，管理多个服务的配置</p><p>- **配置自动化**：便于版本控制和配置管理工具处理</p><p>### 两种格式的关系和使用建议</p><p>**1. 各司其职**</p><p>- **cnf 格式**：负责服务内部的具体配置参数</p><p>- **YAML 格式**：负责服务的编排和部署配置</p><p>**2. 在 Docker 环境中的使用**</p><p>- **docker-compose.yml**：定义服务的部署参数（端口映射、 volumes、环境变量等）</p><p>- **my.cnf/redis.conf**：通过 volumes 挂载到容器中，配置服务的具体参数</p><p>**3. 最佳实践**</p><p>- **保持分离**：将部署配置（YAML）与服务内部配置（cnf）分开管理</p><p>- **版本控制**：将两种配置文件都纳入版本控制系统</p><p>- **环境隔离**：为不同环境（开发、测试、生产）准备不同的配置文件</p><p>### 总结</p><p>- **cnf 格式**：是 MySQL 和 Redis 的原生配置格式，专注于服务内部的详细参数配置</p><p>- **YAML 格式**：是容器编排和配置管理的标准格式，专注于服务的部署和管理</p><p>- **两者配合使用**：在现代容器化环境中，通常同时使用这两种格式，各司其职，共同构成完整的配置体系</p><p>因此，即使在使用 YAML 进行容器编排的情况下，cnf 格式的配置文件仍然是必不可少的，因为它负责定义服务的具体运行参数。</p>
